What is CyberShield?
CyberShield is a real-time cyber threat intelligence dashboard: a single, always-on screen that turns the constant churn of security reporting into an ordered, prioritized picture. Instead of juggling a dozen feeds, bookmarks and mailing lists, an operator opens one page and sees what is happening across the global threat landscape right now — already collected, deduplicated, ranked by severity, and enriched with context.
Everything runs on its own server layer. The dashboard is fully self-sufficient: it needs no external database service, no paid API subscriptions and no third-party aggregation account. Feeds are fetched from the public internet at request time, cached intelligently in memory, and served through a small set of purpose-built API routes. Drop it on any host and it simply works — the first visit triggers a full harvest of all sources, and every visit after that is instant.
It is also designed to be honest about its own state. Pipeline status tells you when data is fresh and when a background refresh is running; the known-exploited catalog carries a visible sync indicator; and the AI analyst clearly labels any verdict produced by its deterministic fallback engine rather than a live model. Nothing on the screen pretends to be more current or more certain than it actually is.

How it works — the intelligence pipeline
Collection happens server-side, on every refresh. Nineteen curated streams — vendor advisories, CERT bulletins, research labs and security aggregators — are polled by the server, parsed from their native XML first. If a source refuses a direct fetch, the request falls through a public RSS-to-JSON converter and then a server-side relay, so a single blocked host never blanks the picture.
Each story is then normalized and enriched: the best available thumbnail is extracted through a hotlink-safe image relay, per-story analyst briefs are distilled, duplicates across sources are collapsed, and everything is ranked by severity, recency and known-exploitation. The result is cached in memory and served as one aggregated snapshot.

How it works — analysis & context
Two context systems sit on top of the raw stream. The first is ground truth: the official CISA Known Exploited Vulnerabilities catalog. The full catalog is fetched server-side and cached, with an auto-synced mirror as fallback, so the multi-megabyte download never blocks the hot path. Stories referencing cataloged CVEs are ranked up, and the exposure gauge at the top of the board summarizes the current exploited-vulnerability load at a glance.
The second is the AI Analyst. Clicking any story opens the investigation drawer and produces a structured, SOC-grade threat brief: threat class, severity rating, what happened, why it matters, and immediate recommended actions. The analysis walks a three-layer chain so it can never dead-end:
1
LIVE MODEL
Configured credentials — any OpenAI-compatible provider — generate the full verdict in real time.
2
FORWARDED AUTHENTICATION
If the hosting gateway injects fresh per-user credentials into the request, those are used instead of a possibly stale file token.
3
OFFLINE ANALYST
A deterministic heuristic brief distilled from the server-side intel pipeline — lede, highlights, CVEs, organizations, severity. Clearly marked as degraded, and never archived in place of a live verdict.
Completed verdicts are archived in SQLite, keyed by the normalized article URL, so re-opening a past investigation is instant. Degraded fallback verdicts are not archived — a later live re-analysis replaces them. The feature is therefore fully usable out of the box, and becomes sharper the moment real model credentials are provided.

Deployment & operations
CyberShield ships as a single deployable unit. Because caching is memory-first and the only database touchpoint is the optional verdict archive, there is no infrastructure to provision: no managed database, no message queue, no worker fleet. Three deployment paths cover every realistic budget, and all of them support custom domains.
PATH A

Vercel — Free Tier

Push the project to GitHub, import it on Vercel, deploy. Framework preset auto-detects; no environment variables are required. Function time limits are already baked into the routes, so the first sync survives the free plan's defaults.

PATH B

Docker — Any Host

A self-contained container image: build it, run it on port 3000, done. The included SQLite file makes the verdict archive work inside the container, giving the full feature set on any VPS or container platform.

PATH C

Render — Free Tier

Connect the repository as a Docker web service. Free instances sleep when idle and wake in roughly forty seconds — the threat-radar boot sequence covers the wake-up, exactly as designed.

NOTE

Restoring Live AI

The analysis uplink reads a provider config (baseUrl + apiKey) and speaks the OpenAI-compatible format — point it at any compatible provider, including local models, to upgrade verdicts from the Offline Analyst to live generation.

OPERATIONS NOTE The first visit after a cold start triggers a full 19-source sync — a few seconds, covered by the boot sequence. Every visit afterwards is served from cache and feels instant. There is no cron, no worker and no maintenance: idle hosts simply start cold, and warm hosts stay warm on traffic.
